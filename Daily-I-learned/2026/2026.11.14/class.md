# 11/14 실습에서 배운 것

주말이라 수업은 없었고, 손목 바코드 작업에서 배운 것을 정리했어요.

## 1. 바코드 인지는 두 단계

- **발견**: "저건 바코드다" → YOLO (학습). 작거나 흐려도 모양으로 빨리 찾음
- **판독**: "내용이 뭐지?" → 찾은 박스만 잘라 흑백 · 확대해서 zxing. 학습하는 모델이 아님
- 판독은 막대 한 칸이 2–3 px 는 돼야 함. 오늘 라벨 박스로 잘라 보니 폭 120 px 미만은 0/73, 200 px 이상은 6/21
- 그래서 박스를 **딱 맞게** 그려야 함 (넓게 자르면 배경이 섞여 판독 실패) → 라벨링 기준이 곧 판독 품질

## 2. 이어서 학습할 때 조심할 것

- 이미 아는 모양에서 출발(전이 학습)하면 적은 사진으로도 빨리 배움 → 시작 가중치로는 좋음
- 하지만 **다른 카메라 사진**으로 이어 학습하면 원래 카메라 성능이 떨어질 수 있음 → 결과는 다른 이름의 모델로 저장
- **일부 클래스만 라벨**된 사진으로 이어 학습하면 나머지 클래스를 잊어버림 (catastrophic forgetting)
- 클래스 수를 바꿔도 (6 → 1) ultralytics 는 맞는 층만 가져오고 마지막 분류 층만 새로 배움

## 3. 남이 만든 모델 출처 확인하기

- 레포 GitHub 기록으로 확인: `git log -- yolo/wrist` → 누가 언제 만들었는지, README · hyp.yaml → 어떤 데이터 · 클래스인지
- 손목 모델은 시뮬로만 학습한 퍽 분할 모델이고 바코드 클래스가 없었음 → 바코드 모델이 따로 필요한 이유가 분명해짐
- Jetson 에 올라간 엔진이 그 모델인지는 파일만 보고는 모름 → 만든 사람에게 묻거나 원본 파일을 확인

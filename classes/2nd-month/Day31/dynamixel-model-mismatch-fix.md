# DYNAMIXEL 모델 불일치 오류 해결

## 실행 환경

- 보드: OpenCR
- 실제 모터: XM430-W210 (모델 번호 1030)
- 스케치: `/home/haeminkim/Desktop/tutlebot1/tutlebot1.ino`
- 코드의 통신 설정: 모터 ID 1, 1,000,000 bps, Protocol 2.0

## 증상과 원인

처음에는 다음 오류가 발생했다.

```text
FAULT (RESET required): ping: check ID/baud/power
DXL lib_error=3, status_error=0
```

`lib_error=3`은 Dynamixel2Arduino의 응답 시간 초과 오류다. 모터에서 응답을 받지 못한 것으로, 전원·배선·ID·통신 속도가 확인 대상이다. 당시 통신 실패의 정확한 원인은 확정하지 않았다.

이후 리셋하고 확인했을 때 오류가 다음과 같이 바뀌었다.

```text
FAULT (RESET required): requires XM430-W350
DXL lib_error=0, status_error=0
```

이번에는 통신 오류가 아니라 **코드의 모델 검사 조건과 실제 모터가 다른 문제**였다. 실제 모터는 XM430-W210인데 코드에서는 XM430-W350만 허용했다. 설치된 Dynamixel2Arduino 라이브러리의 `actuator.h`에서도 `XM430_W210`이 모델 번호 `1030`으로 정의되어 있음을 확인했다.

## 수정 전후

`setup()`에서 모터 모델을 검사하는 조건을 변경했다.

### 수정 전

```cpp
!requireOk(dxl.getModelNumber(DXL_ID) == XM430_W350, "requires XM430-W350") ||
```

### 수정 후

```cpp
!requireOk(dxl.getModelNumber(DXL_ID) == XM430_W210, "requires XM430-W210") ||
```

파일 상단의 기준 하드웨어 주석도 `XM430-W210-T/R (모델 번호 1030)`으로 수정했다.

모델 검사를 제거한 것이 아니라 실제 장비에 맞게 변경했다. 모터 속도, 목표 각도, 제어 방식과 통신 설정은 변경하지 않았다.

## RESET이 필요했던 이유

이 코드의 `requireOk()`는 검사 실패 시 `stopRun()`을 호출한다. FAULT 상태가 되면 OpenCR의 DXL 포트 전원을 끄고 추가 실행 명령을 차단한다.

따라서 FAULT 상태에서 `s` 명령을 반복해도 실행되지 않는다. 원인을 해결한 뒤 보드를 리셋해야 한다. **코드를 수정했다면 리셋만으로 반영되지 않으므로 다시 업로드해야 한다.**

## 다시 실행하기

1. Arduino IDE에서 수정된 파일을 다시 불러온다.
2. 업로드 버튼을 눌러 보드에 수정된 프로그램을 올린다.
3. 시리얼 모니터에서 `READY:` 출력을 확인한다.
4. 줄바꿈을 켜고 다음 명령을 보낸다.

```text
s 1 10 10
```

| 입력 | 의미 |
| --- | --- |
| `s` | 설정을 적용하고 실행 |
| `1` | 제어 게인 Kp = 1 (모터 ID가 아님) |
| 첫 번째 `10` | 최대 명령 속도 10도/초 |
| 두 번째 `10` | 시작 위치 기준 목표 각도 +10도 |

코드는 시작 위치를 0도로 잡고 처음 2초 동안 유지한 뒤 목표 각도를 적용한다. 정지 명령은 `x`다.

## 결과와 배운 점

수정 후 사용자가 정상 동작을 확인했다.

- `s 1 10 10`의 명령 형식은 올바랐다.
- `lib_error=0`, `status_error=0`이어도 프로그램 자체의 모델 검사에서 실패할 수 있다.
- FAULT 메시지의 구체적인 사유를 읽어 통신 실패와 모델 불일치를 구분해야 한다.
- 이번 해결의 핵심은 **W350으로 되어 있던 모델 검사 조건을 실제 모터인 W210으로 맞춘 것**이다.

## 문제점
- 실제만 학습과 합성 섞기를 같은 조건으로 비교한 적이 없었음
- 자동 혼동 행렬(conf 0.001)은 오검출이 부풀려져 실제 사용 기준 성능을 알 수 없었음
- 세 모델 모두 green_cyl 을 green_box 로 똑같이 틀림
- 실시간으로 보니 옆에서 보거나 멀리 있으면 빨간 원기둥·사각기둥을 헷갈림
- 학습한 모델을 로봇이 쓰려면 ROS 토픽으로 결과를 보내는 노드가 필요
- 노트북에 넣은 셀이 VS Code 에 열린 예전 버전 저장으로 덮어써짐




<br>

## 해결 방법

- 시작 가중치·설정·val/test 를 같게 두고 데이터만 바꿔 두 모델을 학습·평가
- conf 0.5 로 다시 세는 혼동 행렬 셀 작성 (배경 행/열로 놓침·오검출 구분)
- 틀린 사진의 박스를 잘라 확인 → 라벨은 맞고, 원기둥을 옆에서 본 장면이 원인
- live_detect.py 로 학습 사진과 같은 조건(MJPG 1280×720)에서 확인, s 키로 틀린 장면 저장
- planning 토픽에 맞춰 perception 패키지와 메시지 작성, colcon build·pytest 로 확인
- 노트북을 고치기 전에 편집기 탭을 닫고 다시 넣음


<br>

## 결과

- 최종 모델 real_ft_1028: 실제 test mAP50 0.969 / mAP50-95 0.728, 어두운 사진 0.995 (합성만 0.615 / 0.371)
- 섞기 mix_ft_v5_1029: test 0.924 (학습 48분, 실제만 5분)
- conf 0.5 혼동 행렬: 정답 103개 중 맞힘 87, 다른 클래스 8, 놓침 8, 오검출 0
- 합성만 오래 학습: best epoch 9 (실제 val 0.867), 이후 하락
- 실시간 검출 32 FPS, 추론 6 ms
- perception 패키지 빌드 성공, pytest 9개 통과

## 수업: CenterPose 객체 추적

- **네 가지 구성 요소의 역할**
  - YOLO: 무엇이 어디에 있는가 → 클래스 · 2D 상자 · 점수
  - CenterPose: 물체가 어떻게 놓였나 → 회전 · 이동 · 상대 크기 (3D 자세)
  - AprilTag: 이 표식은 몇 번인가 → ID · 코너 · 태그 자세
  - PyTorch: 모델을 어떻게 학습하나 (텐서 · 자동미분 · 최적화). YOLO 와 PyTorch 는 대체 관계가 아니라 모델과 학습 도구의 관계
- **YOLO 가 있을 때와 없을 때**: AprilTag 만 쓰면 태그가 보일 때만 정확한 ID. YOLO 를 더하면 태그가 가려져도 외형으로 후보를 찾음. 단, 태그를 다시 읽기 전에는 같은 색 퍽을 같은 ID 로 단정하지 않음
- **YOLO26 을 쓰려면**: 수업은 Isaac ROS 5.0 의 YOLOv8 전용 디코더 기준. YOLO26 은 출력 텐서 해석 · conf/class 변환 · letterbox 를 원본 픽셀로 되돌리기 · Detection2DArray 발행을 직접 구현해야 함. 모델 파일명만 바꿔 기존 디코더에 넣지 않기
- **파일이 바뀌는 흐름**: PyTorch `.pt` → ONNX(계산 그래프) → TensorRT 엔진(대상 GPU 에서 생성) → ROS 디코더 → 검출 메시지
- **검출 · 자세 · 추적은 다름**: 검출 = 프레임마다 후보, 자세 = R·t, 추적 = 이전 물체와 현재 후보 연결. 검출 번호는 영구 ID 가 아님
- **CenterPose 원리**: 중심 히트맵 → 상자 꼭짓점 8개 → PnP 로 자세. 꼭짓점 순서를 모든 영상에서 같게 유지
- **단안 영상의 크기 모호성**: 큰 물체가 멀리 있는 것과 작은 물체가 가까이 있는 것은 비슷하게 보임 → 실측 치수 · 깊이 · 태그로 스케일 검증
- **퍽의 대칭성**: 원기둥은 축 주위로 돌려도 같아 보이고, 사각기둥은 90° 마다 반복 → 태그 방향으로 기준을 정하고, 가려지면 yaw 는 보류
- **AprilTag**
  - 태그 크기는 검은 경계 기준 한 변 (흰 여백 제외)
  - 영상 속 태그 크기 ≈ fx × 한 변 / 거리 (예: fx 600 px, 16 mm 태그 → 0.5 m 에서 약 19 px, 1 m 에서 약 10 px)
  - 태그 중심과 물체 중심은 다름: T_co = T_ct × T_to (60 mm 퍽이면 윗면과 중심이 약 30 mm 차이)
- **좌표계**: ROS 본체 x 앞 · y 왼쪽 · z 위, 카메라 optical 은 x 오른쪽 · y 아래 · z 앞. 길이 m, 각도 rad, 쿼터니언 순서(xyzw) 확인
- **데이터**: 같은 영상의 인접 프레임을 train/test 에 섞으면 과대평가 → 촬영 세션 단위로 나눔. 새 장소 · 조명 · 물체는 따로 holdout 으로
- **추적 상태 전이**: SEARCH → CONFIRM → TRACK, 못 보면 LOST, ID 충돌이나 오래된 측정이면 HOLD (집기 명령 보류). 새 관측 없이 마지막 자세로 계속 움직이지 않음
- **임계값 예시 시작값**: 연속 확인 3 프레임, 관측 최대 나이 0.3 초, 허용 위치 변화 0.15 m → 로봇 속도 · FPS · 지연에 맞춰 조정

## 오늘 YOLO 작업에서 배운 것

- **공정한 비교**: 두 방법을 비교할 때는 시작 가중치 · 설정 · val/test 를 모두 같게 하고 하나만 바꿈. 어제 섞기 모델은 test 일부를 학습해서 비교 불가였음
- **실제만 vs 섞기**: 실제 데이터만 미세조정(test 0.969)이 합성을 섞은 것(0.924)보다 나았고 학습도 10배 빠름. test 가 52장이라 차이는 작게 봄
- **합성을 오래 학습하면**: 합성에 오래 맞출수록 실제 점수는 오히려 떨어짐(best epoch 9). 합성과 실제의 차이(도메인 차이) 때문 → 합성은 짧게, 실제로 미세조정
- **혼동 행렬은 conf 기준을 맞춰서**: ultralytics 자동 혼동 행렬은 conf 0.001 이라 오검출이 부풀려짐 → 실제 사용 기준(conf 0.5)으로 다시 그림
- **같은 실수를 모든 모델이 하면**: 라벨부터 확인. 이번엔 라벨은 맞고, 원기둥을 옆에서 본 장면이라 사각기둥처럼 보이는 게 원인
- **F1-신뢰도 곡선으로 conf 고르기**: 곡선이 평평한 구간(0.2~0.65) 안이면 어떤 conf 를 골라도 성능이 비슷함

## 오늘 ROS 노드에서 배운 것

- **두 탐지 노드를 한 프로세스에**: 광각 · 손목 노드를 한 프로세스에서 돌리면 CUDA context 가 하나라 GPU 메모리 절약
- **큰 이미지 QoS**: 1280×720 이미지를 best_effort 로 프로세스 사이에서 받으면 조각이 유실돼 거의 다 버려짐 → reliable + depth 1 (최신 한 장만)
- **위치 계산 순서**: 손목 depth 우선 → 없으면 태그 코너 PnP → 둘 다 실패하면 has_pose=false 로 명시
- **다수결로 확정**: 신호등 색 · 바코드 문자열은 최근 5 프레임 중 3번 이상 같아야 확정. 신호등이 화면에 없으면 unknown 을 계속 보내서 "못 봄" 과 "꺼짐" 을 구분
- **노드 설정과 모델 클래스 이름은 맞춰야 함**: 노드가 찾는 클래스 이름(puck_cyl, signal_tower)과 모델 출력(red_cyl, traffic_light)이 다르면 후처리가 조용히 안 돎

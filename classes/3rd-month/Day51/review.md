# 복습 — Isaac 생태계와 강화학습 설계 포인트

---

## 1. 시뮬레이션을 쓰는 이유

- 현실에서는 일일이 만들기 어려운 **무수히 많은 경우(상황)를 가상에서 띄워** 학습시킬 수 있다
- 실제 로봇으로 시행착오를 반복할 때 생기는 비용과 위험을 줄일 수 있다

---

## 2. Isaac 관련 용어 정리

| 이름 | 설명 |
|---|---|
| **Isaac Sim** | NVIDIA Omniverse 기반의 로봇 시뮬레이터. 물리 엔진과 렌더링으로 가상 환경을 구성한다 |
| **Isaac Lab** | Isaac Sim 위에서 돌아가는 로봇 학습(강화학습 등) 프레임워크 |
| **Isaac ROS** | ROS 2용 GPU 가속 패키지 모음. Jetson 같은 NVIDIA 장비에서 실제 로봇을 구동할 때 사용 |

### 장비별 역할

- **RTX (데스크톱 GPU)** → **학습 공간**: 시뮬레이션을 돌리면서 모델을 학습
- **Jetson** → **실행 공간**: 학습된 모델로 추론하고 실제로 실행해 보는 곳

---

## 3. 보상(Reward) 설계 시 고려할 점

예시 과제: **SLAM을 하는 모델 설계**

### 로봇에게 기대하는 행동

- 막힘 없이 계속 **전진**하기
- 장애물을 떨어뜨렸을 때 **장애물 회피를 최우선**으로 하기
- **운동학적으로 자연스럽게** 움직이기
- **뒤로 가는 동작은 제외**
- **목표 지점까지 잘 도달**하는지
- 미로에서 **최단 거리를 잘 찾는지**

### 학습이 잘 됐는지 판단하는 기준

- 정책이 목표에 잘 도달했는지는 **보상 점수**로 판단한다
- 그 외에 함께 볼 것
  - 물리적으로 제대로 움직였는지
  - 벽을 어느 정도 **부풀려야(inflation)** 안전하게 잘 움직이는지
  - 지정한 **벽과의 거리를 잘 유지**하는지

### 주의: 보상의 허점

- **의도하지 않은 움직임으로 보상을 받으면 안 된다**
- 점수만 보지 말고 **로봇이 실제로 어떻게 행동하는지 직접 관찰**해야 한다

---

## 4. 시뮬레이션과 현실의 차이 (Sim-to-Real)

물리 세계를 가상에서 **완벽하게 구현할 수는 없다**.

- **배터리** 관련 특성은 완벽하게 재현하지 못한다
- 외부에서 **전선이 꼬이는 사고** 같은 상황은 미리 구상하기 어렵다
- **전력량**은 극한 환경까지 고려해서 설정해야 한다

### Fine-tuning

- 이상적인 (시뮬레이션) 환경에서 학습한 모델을 **실제 환경에 맞게 추가로 다듬는 과정**

---

## 5. 매니퓰레이터 관련

- **TCP (Tool Center Point)**: 엔드 이펙터(end effector)의 기준점

### 물체를 잘 집었는지 확인하는 방법

촉각 센서가 없기 때문에 아래 두 가지로 판단한다.

1. **카메라**로 보고 확인
2. **모터에 걸린 토크**가 얼마인지 확인 → 물체를 잡고 있으면 토크가 걸린다

## 오늘 배운 것
- 길고 복잡한 동작을 정책 하나가 통째로 따라 하면 (모방 학습) 작은 오차가 쌓여 결국 경로를 벗어난다. 학습 오차가 줄어도 실제로 돌리면 더 나빠질 수 있다
- 경로를 흉내 내는 보상보다 "해낸 일" 마다 주는 단계 보상이 무엇을 해야 하는지 알려 준다
- 보상 기준은 먼저 정답 동작으로 지킬 수 있는지 재 봐야 한다. "퍽 2 mm 밀림" 기준은 혁무님 자세로도 못 지켜서 쥐기 보상이 0 이 됐다
- 그리퍼가 퍽을 미는 이유는 조준이 아니라 손 중심이 치우쳐 한쪽 손가락이 먼저 닿기 때문이었다
- 모터가 대답 없으면 코드보다 전원 (OpenCR · 어댑터) 부터 본다
- 카메라 노드가 장치 설정을 덮어쓸 수 있다. usb_cam 이 밝기 기본값 50 을 넣어 광각 화면이 날아가 있었다
- 바코드는 화면 전체보다 바코드에 딱 맞게 잘라야 읽힌다. 막대 한 칸이 2–3 px 는 돼야 하고, 학습으로는 없는 픽셀을 만들 수 없다
- "저건 바코드다" (YOLO, 빠른 발견) 와 "내용이 뭐지" (잘라서 판독) 는 다른 인지라 나눠서 만든다
- 멀티캐스트가 막힌 와이파이에서는 Fast DDS 에 상대 주소를 직접 적어(유니캐스트) 토픽을 찾는다
- OpenCR USB 시리얼은 받을 노트북이 없으면 출력이 막혀서 깜빡임 시간이 깨진다
- Arduino 빌드는 함수 원형을 첫 함수 앞에 자동으로 넣는다 → 구조체 · enum 은 함수보다 위에, template 함수는 피한다

## 문제점
- 모방 학습 3번 모두 혁무님 동작보다 나쁨 (퍽 끝냄 10% · 19% · 6%)
- 집기 정책이 잘 집어도 ② 쥐기가 0% 로 채점됨
- 보고 집기 k2 · k3 도 밀지 않고 쥐기가 0–15%
- Jetson: 팔 작업 거절 (모터 대답 없음), 바코드 결과 안 나옴, robot_cli 에 신호등 없음
- 광각 카메라 화면이 하얗게 날아감
- 손목 바코드 녹화 3개 모두 판독 0, pa06 로 가까이 찍어도 화면 전체로는 1/1064장
- 노트북에서 Jetson 토픽이 안 보임 (멀티캐스트 막힘 · Docker 주소)
- 신호등: 노트북 없이 켜면 깜빡임이 들쭉날쭉, 고친 코드가 빌드 실패로 안 올라감, 리모컨을 끄면 혼자 켜짐
- Jetson 이 미션 중 꺼졌다 켜짐 (정상 종료 기록 없음)

## 해결 방법

- 모방 학습 대신 단계 보상 + 작은 정책으로 바꿈
- 시뮬에서 재 보니 손가락이 퍽을 옆으로 4–5 mm 밀며 쥠 → 쥐기 기준을 옆 · 아래로 나누고 가운데 맞추기 보상 추가
- Jetson: OpenCR · 어댑터 전원 켬, 바코드 읽기 서비스 켬, 인지 다시 켠 뒤 robot_cli 도 다시 켬
- 밝기 +50 원인은 usb_cam 기본값 → launch 에서 v4l2-ctl 로 −20 고정
- 바코드: 원인 = 너무 작음 (막대 한 칸 약 1.5 px) · 휜 스티커 · 흔들림 → 스티커에 딱 맞게 자르는 구조로 (YOLO 박스 → 잘라서 판독)
- Fast DDS 설정 `fastdds_laptop.xml` + `jetson_env.sh` (와이파이 주소만, Jetson 주소로 직접)
- 신호등: 시리얼은 노트북이 있을 때만 출력, 함수를 구조체 아래로 · template 제거, 버튼 하나짜리 값이 2번 연속 와야 인정, `build_sign.sh` (빌드 성공 때만 업로드)

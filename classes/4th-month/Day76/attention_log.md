# Transformer · Attention 일지 (11/23)

> 작성: 김혜민 · 2026-11-23 (월)

오늘은 **11강 Transformer 와 Attention 을 배우고, Attention 한 번을 손계산과 Python (`KQV.py`) 으로 직접 확인한 날**이에요.

- 토큰 → 토큰 ID → 임베딩 (행렬의 한 행) → 위치 정보를 더해 순서 구별
- 같은 입력 X 에서 Q = XWq, K = XWk, V = XWv 를 만들고, Q·K 내적 → √d_k 로 나눔 → softmax → V 가중합
- causal mask 는 미래 위치의 비율을 0 으로 만들어, 학습 때도 생성할 때와 같은 조건으로 연습하게 함
- 실습 ① (Query 바꾸기 · 둘째 Key 가리기) 를 `KQV.py` 로 짜서 실행 → 가중치 합 1, 가린 경우 출력 [2, 0] 확인
- 실수: `sum(e_x)`, 전역 `K` 사용 (매개변수 `k` 는 안 쓰임), 반환 · 받는 순서, f-string 빠짐

<br>

## 1. 토큰에서 벡터로

- 토크나이저가 문장을 부분 단어로 나눔 → 토큰 ID → 임베딩 행렬 E 의 그 행을 꺼냄
- 같은 토큰은 같은 임베딩에서 출발. 위치 정보를 더해야 A→B 와 B→A 를 구별
- 위치 정보 = 순서를 알려 줌, 마스크 = 참고할 범위를 정함 (서로 다른 역할)

<br>

## 2. Q · K · V

- "빨간 컵을 집어" 에서 '컵' 이 어느 컵인지 정하려면 '빨간' 을 같이 봐야 함
  - Q: 무엇을 찾을까 (컵을 설명할 단서)
  - K: 각 단어가 가진 단서
  - V: 그 단어가 실제로 건네는 내용
- 왜 Wq 를 곱하나: '컵' 을 나타내는 일과 '컵을 설명할 말을 찾는' 일이 달라서. Wq · Wk · Wv 는 학습으로 정해지고, 새 문장을 읽을 때도 그대로 씀

| 투영 | 계산 | 역할 | 쓰이는 단계 |
|---|---|---|---|
| Query | Q = XWq | 현재 위치가 찾는 특징 | 점수 |
| Key | K = XWk | 비교할 위치의 특징 | 점수 |
| Value | V = XWv | 출력에 전달할 내용 | 가중합 |

- Q 와 K 는 차원이 같아야 내적 가능. V 는 달라도 됨

<br>

## 3. 계산 순서와 행렬 크기

```
Attention(Q, K, V) = softmax(QKᵀ / √d_k) V
```

| 단계 | 계산 | 크기 | 한 행의 뜻 |
|---|---|---|---|
| 점수 | QKᵀ / √d_k | T × T | 모든 Key 와 비교 |
| 가중치 | 행별 softmax | T × T | 허용 위치 합 = 1 |
| 출력 | 가중치 × V | T × d_v | Value 가중합 |

- √d_k 로 나누는 이유: 차원이 크면 내적 분산이 d_k 만큼 커져 softmax 가 한쪽으로 쏠림 → 크기를 일정하게 맞춤
- softmax: 큰 점수에 더 큰 비중, 한 행의 합은 1

<br>

## 4. 손계산 (강의 예제)

- q = [1, 0], k₁ = [1, 0], k₂ = [0, 1] → 내적 [1, 0] → ÷√2 → [0.707, 0]
- softmax → [0.670, 0.330]
- v₁ = [2, 0], v₂ = [0, 4] → 출력 ≈ [1.340, 1.321]

<br>

## 5. 마스크 · 헤드 · 블록

| 방식 | Query | Key · Value | 참고 범위 |
|---|---|---|---|
| 양방향 self | 입력 토큰 | 같은 입력 | 앞뒤 |
| causal self | 생성 중 토큰 | 같은 시퀀스 | 현재 + 과거 |
| cross | 디코더 상태 | 인코더 출력 | 다른 입력 |

- 헤드 = 자기만의 Wq · Wk · Wv 로 Attention 한 번. 여러 헤드가 서로 다른 관계를 배움 → 이어 붙여 선형층
- 블록 = Multi-head Attention + FFN (각 위치에 같은 신경망), 잔차 연결 (입력을 다시 더함) + LayerNorm
- 원 논문: Attention Is All You Need (Vaswani 외, 2017) Figure 1 · 2

<br>

## 6. KV cache

- 길이 T 의 점수 행렬은 T² 개. 128 → 256 토큰이면 16,384 → 65,536 개
- 생성할 때 과거 토큰의 K · V 를 층별로 저장해 재사용 → 새 Q 로 기존 K 와 비교, 새 K · V 는 캐시에 추가. 대신 메모리가 계속 늘어남
- (Day73 에서 본 "VRAM ≈ 가중치 + KV 캐시" 의 그 KV 캐시)

<br>

## 7. 로봇에서는 (RT-1)

- 지시 "빨간 컵을 집은 뒤 선반에 놓아" → 대상 · 목적지 · 순서 단서
- 영상 · 언어 · 로봇 상태를 모달리티별 인코더로 특징화 → 차원을 맞춰 정책에 넣음
- RT-1 (Brohan 외, 2022): 언어 임베딩이 FiLM 으로 영상 특징 추출을 조절 → TokenLearner 가 토큰 수를 줄임 → Transformer 가 시간순 관측으로 팔 · 베이스 행동 토큰 출력
- 특정 헤드가 '빨간색' 을 담당한다고 말하려면 가중치만 보지 말고 입력을 바꿔 비교하는 검증이 필요

<br>

## 8. 실습 ① `KQV.py`

- [KQV.py](KQV.py): Key 2개, Value 2개로 세 조건을 비교. 강의와 달리 v₂ = [0, 3]

| 조건 | weights | output |
|---|---|---|
| q = [1, 0] | [0.6698, 0.3302] | [1.3395, 0.9907] |
| q = [0, 1] | [0.3302, 0.6698] | [0.6605, 2.0093] |
| q = [1, 0], 둘째 Key 가림 | [1, 0] | [2, 0] |

- 세 조건 모두 가중치 합 1.0
- 마스크는 `True` 인 자리를 `-inf` 로 → `exp(-inf) = 0` 이라 그 위치 가중치가 0

### 고친 실수

| 실수 | 증상 | 고침 |
|---|---|---|
| `e_x.sum(e_x)` | `TypeError: only integer scalar arrays...`. `sum` 괄호 안은 축 번호 | `e_x.sum()` |
| print 에 `f` 빠짐 | `{ }` 가 set 이 되어 `unhashable type` | f-string |
| 반환 `(output, weights)` 를 `weights, output` 으로 받음 | 값이 뒤바뀜 | 순서 맞추기 |
| 조건 제목이 모두 `"Q1="` | 결과 구분 안 됨 | 제목 나누기 |

- **아직 남은 것**: 13번 줄이 매개변수 `k` 대신 전역 `K` 를 씀
  - 파이썬은 함수 안에 `K` 가 없으면 밖 (전역) 에서 찾아 씀. 대소문자가 달라 `k` 와 `K` 는 다른 변수
  - 지금은 같은 값을 넘겨서 결과가 맞지만, 다른 Key 를 넘기면 무시됨 → `q @ k.T`
  - VS Code 에서 `k` 가 흐리게 보인 이유 = Pylance 가 안 쓰인 변수를 dim 처리 (`"k" is not accessed`). 흐린 변수는 오타 신호일 수 있음

### `q.shape[-1]` 이 2 인 이유

- `q = [1, 0]` 의 shape 은 `(2,)`, `[-1]` 은 마지막 값 → 2 = d_k (벡터 안 숫자 개수)
- Query 가 여러 개면 `(3, 2)`, 배치까지면 `(배치, 토큰 수, d_k)`. 벡터 차원은 항상 마지막 축이라 `[-1]` 로 씀
- "차원 2" = 배열이 2차원이란 뜻이 아니라 특징이 2개라는 뜻

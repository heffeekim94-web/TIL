## 2. 교재에 없는 팁 ⭐

### 설정 (MoveIt Setup Assistant)

- ⭐ **양팔 로봇이면 왼팔 · 오른팔을 각각 다른 그룹으로** 지정
- ⭐ **관절 범위는 RViz 나 실제 로봇을 직접 움직여 보면서 정함**. 모양만 보면 안 되고 **선이 꼬이는 각도**도 봐야 함
  - 예) 어떤 관절은 선이 꼬이면 안 되니까 범위를 270° 정도로 제한
  - 범위를 넣으면 관절마다 노란 구(충돌 구)가 보임 → 관절마다 제대로 정의됐는지 확인
- ⭐ 장애물 인식 카메라는 **TCP(손목) 카메라 + 로봇 몸체 카메라를 같이** 쓸 수 있음
- ⭐ 경로를 만들 때 따지는 것: ① 장애물 · 자기 관절과 안 부딪힘 ② 최소한의 움직임 ③ 최소한의 전력

### cuMotion · cuRobo

- ⭐ **cuMotion 은 팔을 직접 움직이는 게 아니라 "경로를 계산해 주는 GPU 백엔드 서버"** 라고 생각하면 됨. 주행 때 nvblox 가 GPU 로 지도를 만들던 것과 같은 관계
- ⭐ **cuRobo 는 로봇팔을 직접 설계할 때** (모터 · 관절 크기부터 정할 때) 많이 씀
- ⭐ **레벨 3 프로젝트 예고**: 로봇 4대가 함께 움직이고 매니퓰레이션하면서 하나의 미션을 풂 → 팔끼리 부딪히지 않게 하는 데 cuMotion 을 많이 쓸 것

### ros2_control · 실제 로봇

- ⭐ **command interface(position / velocity 등)가 모터 드라이버 설정과 같은지 먼저 확인**
- ⭐ **바퀴 축이 반대면 앞뒤만 바뀌고 끝나지만, 로봇팔은 바로 망가질 수 있음**
- ⭐ **실행 전에 반드시 캘리브레이션 테스트**: RViz 에서 관절을 하나씩 움직여 보고 실제 로봇이 똑같이 움직이는지 확인
- ⭐ **Servo = MoveIt 안에 들어 있는 PID 같은 것**. 목표에 도착했을 때 TCP · 관절이 지정한 위치에 갔는지 보고 오차를 알아서 보정. 위치는 모터 엔코더나 카메라로 읽음

### 집게가 퍽을 잡았는지 판단 (임피던스) — 우리 로봇에 바로 해당

- ⭐ 위치 오차가 생기는 이유는 두 가지: **전력이 부족하거나, 외력** 때문에 토크가 생각대로 안 걸림
- ⭐ 다른 관절에는 굳이 안 써도 됨. **집게가 퍽을 집었는지 판단할 때 씀**
- ⭐ **우리 로봇엔 힘 센서가 없음** → **실험으로 값을 구해야 함**
  - 집게로 퍽을 집고 들어 올릴 때 토크가 얼마나 걸리는지 측정
  - 그 값을 기준으로 토크가 걸렸으면 "잡음", 안 걸렸으면 "못 잡음"
  - 허용 범위보다 작게 걸리면 잡았다가 미끄러져 떨어질 수도 있음 → 이것도 실험으로
- ⭐ **선생님 방법: 토크 + 손목 카메라를 같이 봄**
  - 손목 카메라는 계속 퍽을 보고 있음. 퍽을 집어 올렸으면 **카메라 기준 퍽 위치가 고정**되어 같이 움직여야 함
  - 위치가 바뀌거나 멀어지면 집기 실패 · 떨어뜨림으로 판단 → **비전 쪽 할 일**

### 집기 작업 · 실패 처리

- ⭐ 아직은 목표 자세 하나로 전체 집기 작업을 만들 수 없음 → **단계마다 나눠서 검증**: 접근이 잘 되는지, 잘 집었는지, 들어 올렸을 때 안 떨어지는지. 경로만 나왔다고 끝이 아님
- ⭐ **퍽을 옮기다 떨어뜨리면 → 재탐색**. 팔만으로는 못 찾고 **로봇 차체가 움직이면서** 찾아야 함
- ⭐ 선생님 예제에는 이미 nvblox 연결이 들어가 있음. 장애물 때문에 팔이 닿을 수 없는 곳이면 **로봇이 이동해서 팔이 닿는 위치까지 간 다음** 집도록 함

### 정책학습 (강화학습)

- ⭐ **에피소드에 실패 상황도 넣기**: 퍽이 떨어졌을 때, 퍽이 이상한 위치에 있을 때
- ⭐ **초기 위치를 최대한 랜덤으로** 흩어서 다양한 자세로 학습시킬수록 좋음
- ⭐ 관측에 넣을 것: 관절 위치 · 속도, TCP 오차(위치 오차, 토크 오차). **집게 상태는 센서가 없어서 직접은 알 수 없음**
- ⭐ **모터 매핑은 나중에**: 먼저 움직임만 학습 → 출력은 선속도 · 각속도 같은 값 → 나중에 브리지에서 각 모터 드라이버에 맞춰 연결
- ⭐ **로봇팔은 특히 급격한 행동이 있으면 안 됨** → 급격한 행동에 벌점. "어느 정도가 급격한지"는 팀 로봇에 맞춰 조정
  - 차체가 높은 팀은 무게중심 영향을 많이 받음
- ⭐ **처음부터 로봇 전체로 학습하지 않기**: 팔을 바닥에 고정하고 팔만 먼저 학습 → 잘 되면 차체 붙이기
  - 선생님도 OpenArm 학습 때 한쪽 팔만 바닥에 고정해 학습한 뒤 하나씩 추가함
- ⭐ **작은 Task 들을 먼저 만들고 이어 붙이기**
  - 예) 미션 A = Task 5개 → 5개를 한 번에 수행하는 정책을 학습 → A 미션 정책 완성 → 차체와 이어서 "A 에서 B 로 가서 퍽을 옮겨라" 같은 전체 미션
  - **처음부터 한 번에 연결해서는 못 만듦**. 연결은 스크립트로도 되지만 정책으로 만드는 게 가장 좋음

### 모방학습

- ⭐ **팀마다 팔이 있으니 하나는 리더, 하나는 팔로워**로 만들어 사람이 리더를 움직여 시연 데이터를 모으는 방법
- ⭐ 다른 방법: **카메라로 사람 팔을 찍고 관절을 추적**해 시연으로 쓰기 → 우리가 하기엔 시간이 많이 듦
- ⭐ 요즘 피지컬 AI 스타트업(특히 국내)은 **모방학습 데이터 수집 장비**(사람이 입는 센서 장비 등)를 많이 만듦. **1등 팀 상품 로봇팔도 이런 모방학습 세트** *(불확실)*
- ⭐ Mimic 은 다음 달에 시간이 되면 해 볼 예정
- ⭐ **강화학습 vs 모방학습은 작업에 따라 다름**. 뚜껑 열기처럼 **손재주가 필요한 작업**은 강화학습으로는 거의 못 만들고 **모방학습 데이터가 필요**

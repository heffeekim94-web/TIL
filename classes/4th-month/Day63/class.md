# 11/04 실습에서 배운 것

강의 노트를 확인하지 못해서, 오늘 YOLO 작업에서 배운 것을 정리했어요.

## 1. 사진 한 장으로 카메라 자세 재기

- 렌즈 왜곡(fisheye)을 먼저 펴야 직선이 직선으로 보임 → 각도 계산이 가능
- **숙임(pitch)**: 실제로 수직인 기둥들은 사진에서 한 점으로 모임(소실점). 그 점이 화면 중심에서 얼마나 떨어졌는지로 카메라가 아래로 숙인 각도를 구함 → 약 22°
- **높이**: 높이를 아는 물체(벽 0.39 m)의 위 · 아래 끝을 보는 각도 두 개와 숙임으로 카메라 높이를 구함 → 기둥 2개에서 0.57 · 0.59 m
- 팀 URDF 값(40°)과 실물이 다르면, 그 URDF 로 만든 합성 데이터도 실물과 다른 장면이 됨

## 2. 합성 데이터는 "보이는 장면"을 실물에 맞춰야 함

- 같은 경기장이라도 카메라가 40° 숙이면 바닥과 팔이 주로 보이고, 22° 면 멀리 있는 물체와 벽 너머까지 보임
- 한 각도로만 만들지 않고 실물 값 주변(18 · 22 · 26°)으로 흔들어 주면 장착 오차에도 버팀
- 대상 거리 · 배경 밝기 범위도 실물에서 본 값에 맞춤 (실물이 더 밝고 더 멀리 봄)
- 남의 코드(팀 저장소)를 고치지 않고 바꾸고 싶은 값만 넣어 실행하는 **감싸는 스크립트**를 만들면, 원본과 충돌하지 않음

## 3. 1단계가 좋아져도 최종 성능은 그대로일 수 있음

- 합성만으로 학습한 1단계는 실물 test 0.597 → 0.673 으로 확실히 나아짐
- 하지만 실물로 미세조정(2단계)하면 실물 데이터가 많이 가르쳐 줘서, 1단계 차이가 거의 사라짐 (conf 0.5 맞힘 모두 83/103)
- 비교할 때는 **바꾼 것 하나만** 다르게 (시작 가중치만 다르고 2단계 설정 · 데이터 · test 는 같게)
- test 가 52장뿐이면 0.02~0.03 차이는 우연일 수 있음 → 결론을 내기 전에 test 를 늘려야 함

## 4. 모델을 바꿔도 같은 오류가 남으면 데이터를 봐야 함

- 세 모델 모두 초록 원기둥 → 초록 상자 7~9개, 빨간 상자 놓침 5~6개
- 합성 · 시작점을 바꿔도 그대로인 오류는 학습 방법보다 **실물 사진 · 라벨**(멀리 있음, 가려짐, 라벨 실수)이 원인일 가능성이 큼 → 틀린 사진을 직접 열어 봄

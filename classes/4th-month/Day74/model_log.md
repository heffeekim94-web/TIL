# 로봇 모델 · gemma4 활용 고민 일지 (11/19)

> 작성: 김혜민 · 2026-11-19 (목)

오늘은 **"모델" 이 정확히 뭔지 다시 잡고, gemma4 를 로봇에 어떻게 쓸지 고민한 날**이에요.

- RoboCook (CoRL 2023) 을 보고 "남이 만든 로봇 모델을 내가 써 볼 수 있나" 를 따져 봄
- 모델 = 입력 → 출력 함수 + 데이터로 배운 숫자 (가중치). 숫자 파일만으로는 안 돌고 돌리는 코드 · 환경이 같이 필요
- 행동을 관절 공간으로 내는 모델은 그 로봇에 묶이고, 작업 공간 (도구 자세) 으로 내는 모델은 IK 로 다른 팔에도 옮길 수 있음
- gemma4 는 팔을 직접 움직이는 "손" 이 아니라 무엇을 · 언제 · 다시 할지 정하는 "머리" 로 쓰는 게 맞음
- 드라이브 `Research papers` 에 Open X-Embodiment 데이터셋 개요 시트가 추가됨

<br>

## 1. RoboCook 을 써 볼 수 있을까

- [RoboCook](https://hshi74.github.io/robocook/): 로봇 팔이 도구 15종을 바꿔 가며 반죽을 다뤄 만두 · 쿠키를 만드는 연구
- 구조: RGB-D 카메라 4대 → 포인트 클라우드 → 도구 분류 → GNN 동역학 모델 ("이렇게 누르면 반죽이 어떻게 변하나") → 플래너
- VLA 처럼 거대 모델이 바로 행동을 내는 게 아니라 **모델 기반 계획** 방식. 데이터도 도구당 약 20분으로 적음

| | RoboCook | VLA (SmolVLA, π0) |
|---|---|---|
| 입력 | 포인트 클라우드 | 이미지 + 언어 |
| 핵심 | 동역학 예측 + 계획 | 모델이 바로 행동 출력 |
| 데이터 | 도구당 약 20분 | 수만 ~ 수백만 시연 |

- 공개된 것: 코드, 데이터, 학습된 동역학 체크포인트 (`dy_model.pth`, 데이터셋 안), 도구 3D 모델
- 노트북에서 가능한 것: 공개 데이터로 동역학 모델 · 도구 분류기 학습 · 평가, 시뮬레이터 실험
- 걸림돌: 2023년 환경 (Ubuntu 18/20 + 옛 PyTorch) 이라 RTX 5060 (sm_120) 에선 PyTorch 2.7 이상으로 환경을 새로 만들어야 함. Isaac Lab venv 와는 분리
- 실제 만두 만들기는 팔 · 카메라 4대 · 도구 15종이 필요해서 어려움

<br>

## 2. 같은 로봇팔이 있어야 하나

- 아님. 모델이 행동을 **어떤 형태로 내느냐**에 달림

| 행동 표현 | 예 | 다른 팔에서 |
|---|---|---|
| 관절 공간 | "1번 관절 +3°" | ❌ 관절 수 · 길이가 다르면 의미 없음 |
| 작업 공간 | "도구를 (x, y, z) 로, 30° 돌려 2cm 누르기" | ✅ IK 로 바꿔 실행 가능 |

- RoboCook 은 작업 공간 방식. 대신 도구 모양 · 반죽 재질 · 카메라 구성 · 좌표계 · 팔 힘은 맞춰야 함
- 내가 학습한 `stand_sB` 정책은 관절을 보고 관절 목표를 내서 **그 팔에 묶여 있음**
- 로봇 형태가 달라도 통하게 하려는 분야가 **cross-embodiment**. Open X-Embodiment · π0 · GR00T 가 여러 로봇 데이터를 같이 학습하는 이유

<br>

## 3. "모델" 이라는 말

- 모델 = 입력을 넣으면 출력을 내는 함수 + 그 숫자를 데이터로 배운 것. `y = ax + b` 에서 식 모양이 구조, a · b 가 가중치
- 학습 = 숫자를 맞추는 과정, 추론 = 숫자를 고정하고 새 입력을 넣는 것

| | 구조 | 입력 → 출력 |
|---|---|---|
| YOLO | CNN | 이미지 → 박스 |
| `stand_sB/model_600.pt` | 작은 MLP | 관절 상태 → 관절 명령 |
| RoboCook `dy_model.pth` | GNN | 반죽 점 + 도구 동작 → 변형된 반죽 |
| `gemma4` | Transformer (7.5B) | 글자 · 이미지 → 다음 글자 |

- 모델 파일은 숫자 덩어리. 돌리는 코드가 따로 필요 (gemma4 → Ollama, `model_600.pt` → Isaac Lab play 스크립트)
- 같은 단어, 다른 뜻: **AI 모델** (배운 함수) / **동역학 모델** (세상이 어떻게 변하나 예측, 학습일 수도 공식일 수도) / **3D 모델** (모양 파일) / **로봇 모델** (URDF · USD 설명서)

<br>

## 4. gemma4 로 뭘 할까

- gemma4 가 직접 팔을 못 움직이는 이유: 답 하나에 약 1–3초 (제어는 초당 수십 번), 출력이 글자, 좌표가 "왼쪽 위쯤" 수준
- 그래서 층을 나눔

```
사람 "쓰러진 퍽 세워 줘"
 → gemma4 (상위 판단): 사진 보고 stand_up(puck_1) 호출
 → 스킬 (하위 제어): YOLO 로 위치 → RL 정책으로 세우기
 → gemma4 (확인): 다시 사진 → 섰나? 아니면 재시도
```

| 아이디어 | 난이도 |
|---|---|
| ① 작업 후 사진으로 성공 · 실패 판정 | 쉬움 |
| ② 말 → 스킬 함수 호출 (tool calling) | 보통 |
| ③ 음성 명령 (gemma4 audio) | 보통 |
| ④ 실패하면 다시 계획 (① + ②) | 어려움 |

- 추천 순서: ① (녹화한 영상 프레임으로, 로봇 없이) → ② (함수는 `print` 만) → ④ 폐루프. 나중에 하위 스킬을 VLA 로 바꾸면 VLA 실습으로 이어짐
- 제약: Isaac Sim (약 4GB) + gemma4 (약 4.6GB) 는 8GB 초과. 정밀 수치는 기존 측정 코드에 맡김

실제 상황을 따라가는 이야기 형식으로 설명해 볼게요. 바깥 PC가 "카메라를 오른쪽으로 돌려"라고 명령을 보낸다는 장면을 가정했어요.

## 프롤로그: 규칙을 정해 두기 ([1~53줄](opencr_lite.ino#L1-L53))

이야기가 시작되기 전에 이 세계의 규칙부터 정해 둡니다.

```cpp
constexpr uint32_t CYCLE_US = 10000;          // 10ms마다 한 번 일한다 (100Hz)
constexpr uint32_t COMMAND_TIMEOUT_MS = 200;  // 200ms 동안 명령이 없으면 멈춘다
constexpr float SPEED_UNIT = 1.374f * PI / 180.0f;  // 모터 속도 1단위 = 1.374°/s
constexpr float MAX_RAD_S = 1.0f;             // 아무리 빨라도 1 rad/s까지
constexpr int32_t MAX_POSITION = 1048575;     // 확장 위치 모드의 한계 (±256바퀴)
constexpr int32_t TRAVEL_TOLERANCE = 8;       // 범위 검사 때 봐주는 여유 (8틱 ≈ 0.7°)
```

- **`SPEED_UNIT`**: XM430은 속도를 "0.229 rpm 단위"로 받아요. 0.229 rpm은 1.374°/s이고, 이를 rad/s로 바꾼 값(약 0.024)이에요. PC가 보내는 rad/s를 이 값으로 나누면 모터가 이해하는 숫자가 됩니다. 1 rad/s는 약 41단위예요.
- **`Reg`** ([19~24줄](opencr_lite.ino#L19-L24)): 모터 내부 메모리(컨트롤 테이블)의 주소록이에요. 132번지에는 현재 위치, 116번지에는 목표 위치가 들어 있는 식이에요.
- **`Axis`** ([26~32줄](opencr_lite.ino#L26-L32)): 모터 한 대의 신상 카드예요.
  - `home`, `lower`, `upper`: 홈 위치와 홈 기준 이동 한계
  - `position`: 지금 위치
  - `origin`: 이번 부팅에서 계산한 실제 홈 좌표
  - `applied`: 지금 모터에 걸려 있는 속도
  - `profile`, `goal`: 모터에 써 넣은 속도 프로파일과 목표 위치
  - `ready`: 준비 완료 여부
- **`axes[]`** ([35~38줄](opencr_lite.ino#L35-L38)): 팬은 ±180°(±2048틱), 틸트는 ±120°(±1365틱)까지만 움직이도록 정해요.
- **`motors(Serial3, 84)`**: 모터와 대화하는 전화선이에요. OpenCR의 DYNAMIXEL 포트가 `Serial3`이고, 84번 핀은 송신/수신 방향을 바꾸는 스위치예요.
- **`fault_*` 변수들** ([49~53줄](opencr_lite.ino#L49-L53)): 사고 기록부입니다. 사고가 나면 **첫 번째 사고만** 여기에 적어요.

## 1막: 잠에서 깨어나기 (`setup()`, [294~305줄](opencr_lite.ino#L294-L305))

보드에 전원이 들어오면 지휘자는 이렇게 시작해요.

1. **USB를 연다**: 115200bps로 PC와의 통로를 엽니다.
2. **모터 전화선을 연다**: 1Mbps 속도에 Protocol 2.0을 씁니다.
3. **단체 문자 양식을 미리 만든다**: 매번 두 모터에게 한꺼번에 묻고 지시할 거라서, Sync Read/Write 패킷에 "받는 사람: 11번, 12번"을 미리 적어 둡니다. 쓰기 패킷에는 "112번지부터 8바이트"(Profile Velocity 4B + Goal Position 4B)라고 고정해 둬요.
4. **1초 기다린다**: 모터가 전원을 받고 부팅할 시간을 줍니다.
5. **두 모터를 차례로 깨운다**: `prepareMotor(0)`, `prepareMotor(1)`을 호출하고, 하나라도 실패하면 바로 `latchFault()`로 영구 정지 상태가 됩니다.

### 모터 깨우기 의식 (`prepareMotor()`, [188~226줄](opencr_lite.ino#L188-L226))

지휘자가 모터 한 대 한 대에게 하는 면접이에요. 질문 하나라도 틀리면 즉시 불합격입니다.

| 순서 | 하는 일 | 왜 |
|---|---|---|
| ① `ping` | "거기 있니?" | 연결 확인 |
| ② 모델 번호 | "XM430-W350 맞니?" | 다른 모터면 단위가 달라서 위험 |
| ③ 토크 OFF, 워치독 0 | 일단 힘을 빼고 감시도 끈다 | 설정을 바꾸려면 토크가 꺼져 있어야 함 |
| ④ Homing Offset = 0? | 누가 영점을 몰래 옮겨 놨는지 확인 | 0이 아니면 위치 계산이 다 틀어짐 |
| ⑤ HW 에러 = 0? | 과열, 과부하 같은 기존 고장 확인 | 고장 난 채로 움직이지 않기 |
| ⑥ Drive Mode 정리 | `drive & ~12`로 bit 2, 3만 끄고 나머지(회전 방향 bit 0)는 유지 | bit 2(시간 기반 프로파일)가 켜져 있으면 속도 단위가 시간으로 바뀌고, bit 3(목표를 쓰면 자동 토크 ON)은 예상치 못한 동작을 일으킴 |
| ⑦ Operating Mode = 4 | **확장 위치 제어 모드** | 한 바퀴를 넘어서도 위치를 셀 수 있음 |
| ⑧ Velocity Limit 읽기 | 1~1023 범위인지 확인 | 나중에 속도 상한으로 사용 |
| ⑨ 현재 위치 → origin 계산 | (아래에서 설명) | 이번 부팅의 홈 좌표 정하기 |
| ⑩ 최종 세팅 | 가속도 8, 프로파일 1, 목표 = 현재 위치, 토크 ON, 워치독 10 | 제자리에 힘을 주고 버티는 상태로 출발 |

**⑨ origin 계산 ([207~217줄](opencr_lite.ino#L207-L217))이 이 함수의 핵심이에요.**
확장 위치 모드에서는 전원을 켤 때마다 위치 값이 "몇 번째 바퀴인지"에 따라 달라질 수 있어요. 그래서 이렇게 계산합니다.

```cpp
relative = (position - home) % 4096;   // 한 바퀴 안에서 홈과의 차이
if (relative > 2048) relative -= 4096; // -2048 ~ +2048 범위로 접기
if (relative < -2048) relative += 4096;
origin = position - relative;          // 현재 바퀴 기준의 '진짜 홈' 좌표
```

예를 들어 틸트가 지금 `6200`틱이라고 해볼게요. `6200 - 2048 = 4152`이고, `% 4096`을 하면 `56`이에요. 홈에서 56틱(약 5°) 떨어져 있다는 뜻이고, origin은 `6200 - 56 = 6144`가 됩니다. 이후의 모든 위치는 이 origin을 기준으로 따져요.

그다음 두 가지를 추가로 검사해요.
- 켜졌을 때 이미 허용 범위(틸트 ±120°) 밖에 있으면 `startup_range` 실패로 처리합니다.
- origin에 이동 한계를 더한 값이 확장 모드의 한계(±1048575)를 넘으면 `origin_range` 실패로 처리합니다.

**⑩ 워치독 값 10의 의미**: 모터의 Bus Watchdog 단위가 20ms라서 10 × 20ms = 200ms예요. 200ms 동안 보드에서 아무 패킷도 오지 않으면 **모터가 스스로 멈춥니다.** 보드가 멈추거나 죽어도 모터는 안전하다는 뜻이에요.

### 꼼꼼한 설정 도우미 (`configure()`, [85~92줄](opencr_lite.ino#L85-L92))

`configure()`는 "값을 바꿔라"를 세 단계로 처리해요.
1. 먼저 읽어 보고, 이미 원하는 값이면 아무것도 안 합니다. 불필요한 쓰기를 줄여서 EEPROM 수명을 아끼는 거예요.
2. 다르면 씁니다.
3. 쓴 다음 다시 읽어서 정말 바뀌었는지 확인하고, 안 바뀌었으면 `verify` 실패로 처리해요.

## 2막: 끝없는 하루 (`loop()`, [307~316줄](opencr_lite.ino#L307-L316))

이제 보드는 아래 장면을 1초에 수만 번 반복해요.

```cpp
void loop() {
  // 장면 1: 경비원 순찰
  if (command_active && (!Serial || millis() - command_ms >= 200))
    stopMotion();

  // 장면 2: 우편함 확인
  readCommands();

  // 장면 3: 시계 확인 — 10ms가 안 지났으면 아무것도 안 함
  if (faulted || micros() - cycle_us < 10000) return;
  cycle_us = micros();

  // 장면 4: 본 업무 — 위치 확인 + 속도 반영
  if (!readPosition() || !writeSpeed()) { latchFault(); return; }
  ++sample;
}
```

### 장면 1: 경비원 순찰
"움직이라는 명령을 받아서 움직이는 중"(`command_active`)인데 둘 중 하나라도 해당하면 즉시 멈춰요.
- USB 연결이 끊겼다 (`!Serial`)
- 마지막 `v` 명령 이후 200ms가 지났다

PC는 계속 `v` 명령을 보내 줘야 해요. 그만 보내면 PC가 죽었다고 보고 멈춥니다. 이런 방식을 **데드맨 스위치**라고 해요.

> 💡 안전장치가 두 겹이에요.
> - 소프트웨어 타임아웃(장면 1): **PC가 죽으면** 보드가 모터를 멈춥니다.
> - 모터의 Bus Watchdog: **보드가 죽으면** 모터가 스스로 멈춥니다. 보드가 살아 있으면 10ms마다 Sync Read를 보내서 워치독을 계속 리셋해 줘요.

### 장면 2: 우편함 확인 (`readCommands()`, [272~292줄](opencr_lite.ino#L272-L292))

USB로 들어온 글자를 **한 번에 최대 64자까지만** 꺼내요. 너무 많이 읽느라 제어 주기를 놓치면 안 되니까요.

- 글자는 `line[]` 버퍼에 한 자씩 쌓아요.
- `\n`(줄바꿈)이 오면 한 줄이 완성된 것이니 `command(line)`으로 넘깁니다.
- `\r`은 무시해요. 윈도우식 줄바꿈 `\r\n`에 대비한 거예요.
- **수상한 글자**(제어 문자, 한글 같은 ASCII 밖 문자)가 오거나 **줄이 63자를 넘으면**, 즉시 `stopMotion()`을 하고 `discard = true`로 그 줄의 나머지를 줄바꿈이 나올 때까지 버려요. 깨진 데이터로 모터를 움직이지 않기 위해서예요.

`static` 변수를 쓰기 때문에 한 줄이 여러 번의 loop에 나눠 들어와도 이어 붙일 수 있어요.

### 장면 2-1: 편지 해석 (`command()`, [247~270줄](opencr_lite.ino#L247-L270))

| 받은 줄 | 반응 |
|---|---|
| `p` | 현재 위치 보고 (사고 상태여도 응답) |
| `x` | 즉시 정지 (사고 상태여도 동작) |
| (사고 상태에서) 그 외 | 무시 |
| `v`로 시작하지 않음 | **모르는 명령이니 정지** |
| `v A B` | 속도 명령 해석 |

`v 0.3 -0.1`이 오면 이렇게 처리해요.
1. `strtof`로 숫자 두 개를 읽습니다.
2. 숫자마다 검사합니다.
   - 숫자가 맞는가? (`cursor == end`이면 숫자가 아님)
   - NaN이나 무한대가 아닌가?
   - |속도| ≤ 1.0 rad/s 인가?
   - 모터의 Velocity Limit 이하인가?
3. 첫 숫자 뒤에는 반드시 공백이 있어야 하고, 두 번째 숫자 뒤에는 공백 말고 아무것도 없어야 해요. `v 0.3 -0.1 abc` 같은 줄은 정지로 처리됩니다.
4. 모두 통과하면 rad/s를 모터 단위로 바꿔요. `0.3 / 0.024 ≈ 12`, `-0.1 / 0.024 ≈ -4`.
5. `requested[] = {12, -4}`에 **적어 두기만 하고**, 시각을 기록한 뒤 `command_active = true`로 바꿔요.

여기서 중요한 점은 **`command()`가 모터에 직접 아무것도 쓰지 않는다**는 거예요. 주문서만 써 두고, 실제 반영은 장면 4가 해요. 명령 해석과 모터 I/O가 분리돼 있어서 모터 통신이 항상 10ms 리듬에 맞춰 일어나요.

> ⚠️ 작은 함정: `speed / SPEED_UNIT`을 정수로 바꿀 때 소수점을 버리기 때문에, **|속도| < 약 0.024 rad/s(1.4°/s)이면 0이 되어 정지**해요.

### 장면 3: 시계 확인
마지막 본 업무 이후 10ms가 지나지 않았거나 사고 상태(`faulted`)면 여기서 `return`해요. 그래서 1초에 수만 번 도는 loop 중에서 **본 업무는 정확히 100번만** 실행됩니다.

### 장면 4-1: 정찰 (`readPosition()`, [111~134줄](opencr_lite.ino#L111-L134))

두 모터에게 **한 번의 단체 질문(Sync Read)으로** 세 가지를 물어봐요.

**① "지금 어디 있니?" (132번지, 4바이트)**
- `position - origin`으로 홈 기준 위치를 계산해요.
- 허용 범위 ± 8틱을 벗어나면 `travel_range` 사고로 처리합니다.

**② "힘 주고 있니? 아픈 데 없니?" (64~70번지, 7바이트)**
- 64번지(Torque Enable)부터 70번지(Hardware Error)까지 **한 번에 연속으로** 읽는 요령을 써요.
- `data[0]`(토크)이 1이 아니면 `torque_off` 사고예요. 누군가 토크를 껐거나 모터가 스스로 꺼진 경우예요.
- `data[6]`(70 − 64 = 6번째, HW 에러)이 0이 아니면 `hardware_error` 사고예요.

**③ "워치독 터진 적 있니?" (98번지, 1바이트)**
- 워치독이 발동하면 모터는 이 값을 -1로 바꾸는데, 1바이트로 읽으면 `255`가 돼요.
- 255면 `watchdog` 사고로 처리합니다.

단체 질문 도우미 `readBoth()` ([94~108줄](opencr_lite.ino#L94-L108))는 다음을 확인해요.
- 답장이 정확히 2통 왔는지
- 순서가 11번, 12번이 맞는지
- 에러 플래그가 없는지
- 길이가 맞는지

하나라도 어긋나면 `sync_read` 또는 `sync_reply` 사고예요.

### 장면 4-2: 지시 (`writeSpeed()`, [160~186줄](opencr_lite.ino#L160-L186))

이 코드에서 **가장 영리한 부분**이에요. 모터를 속도 모드가 아니라 **위치 모드**로 돌리면서 속도 제어를 흉내 내요.

```
"0.3 rad/s로 오른쪽으로 가" 를 이렇게 바꿔 말한다:
   → "Profile Velocity = 12 로,  Goal = 오른쪽 끝(origin + upper) 으로 가"
```

- **속도의 크기**는 Profile Velocity에 넣어요. "이 속도 이하로 이동해"라는 뜻이에요.
- **속도의 부호**로 목표 지점을 정해요. 양수면 위쪽 한계, 음수면 아래쪽 한계예요.
- **속도가 0이면** 목표를 현재 위치로 두고 Profile은 1로 둬요. Profile을 0으로 쓰면 XM430은 "속도 제한 없음"으로 해석해서 최고 속도로 튀어 버려요. 그래서 0 대신 1을 씁니다 ([173줄 주석](opencr_lite.ino#L173)).

이렇게 하면 좋은 점이 있어요. PC가 계속 "오른쪽으로" 명령을 보내도, 모터는 **한계 지점에 도착하면 스스로 감속해서 멈춰요.** 이동 범위 밖으로 나가는 게 물리적으로 불가능한 구조예요.

진행 순서는 이렇습니다.
1. `requested`와 `applied`가 같으면, 즉 바뀐 게 없으면 아무것도 안 해요. 불필요한 통신을 줄이는 거예요.
2. 바뀐 축만 profile과 goal을 새로 계산합니다.
3. **Sync Write 한 번**으로 두 모터에 각 8바이트(Profile + Goal)를 동시에 써요.
4. 곧바로 Sync Read로 112번지 8바이트를 **다시 읽어서** 쓴 값과 한 바이트도 다르지 않은지 `memcmp`로 비교해요. 다르면 `profile_verify` 사고예요.
5. 확인이 끝나면 `applied = requested`로 "반영 완료"를 표시합니다.

### 장면 4-3: 출석 도장
모든 일이 성공하면 `++sample`을 해요. 성공한 주기 수를 세는 카운터예요. PC는 `p` 응답의 SAMPLE 값이 계속 늘어나는지 보고 보드가 살아서 일하고 있다는 걸 알 수 있어요.

## 3막: 보고하기 (`sendPosition()`, [229~245줄](opencr_lite.ino#L229-L245))

PC가 `p`를 보내면 한 줄로 대답해요.

```
P1 15234 512 -300 0
│  │     │   │    └ FAULT (0=정상, 1=사고)
│  │     │   └ 틸트 위치 (홈 기준 틱)
│  │     └ 팬 위치 (홈 기준 틱)
│  └ SAMPLE (성공한 주기 수)
└ 프로토콜 버전 표시
```

사고 상태라면 그 앞에 진단 한 줄이 먼저 나와요.
```
F1 travel_range 12 132 1400 0 0
   │            │  │   │    │ └ 모터 status 에러
   │            │  │   │    └ 라이브러리 에러 코드
   │            │  │   └ 문제의 값
   │            │  └ 레지스터 주소
   │            └ 모터 ID
   └ 사고 이유
```

사람이 아니라 **프로그램이 파싱하기 쉽게** 설계된 형식이에요.

## 4막: 사고가 났을 때

### 사고 기록 (`failure()`, [55~65줄](opencr_lite.ino#L55-L65))
- **처음 한 번만** 기록하고, 그 뒤의 사고는 덮어쓰지 않아요. 연쇄 사고가 나도 **최초 원인**이 남아 있어야 디버깅할 수 있으니까요.
- 항상 `false`를 돌려줘요. 그래서 이런 관용구가 가능해져요.
  ```cpp
  return (성공조건) || failure("이유", ...);
  ```
  성공하면 `true`, 실패하면 기록을 남기고 `false`가 돼요. 코드 곳곳에 이 패턴이 쓰여 있어요.

### 멈추기 (`stopMotion()`, [136~151줄](opencr_lite.ino#L136-L151))
1. `command_active = false`로 바꾸고, 요청 속도와 반영 속도를 모두 0으로 만들어요.
2. 축마다 현재 위치를 읽어서 **목표 위치 = 현재 위치**로 써요. 모터는 그 자리에 힘을 주고 버팁니다.
3. 이 과정마저 실패하면, 즉 통신이 안 되면 사고 상태로 바꾸고 **토크를 꺼 버려요.** 힘을 빼서 축이 자유롭게 돌게 하는, 최후의 안전 조치예요.

### 영구 정지 (`latchFault()`, [153~156줄](opencr_lite.ino#L153-L156))
`faulted = true`로 바꾸고 `stopMotion()`을 호출해요. 그 뒤로는:
- loop의 장면 3에서 매번 `return`하니까 본 업무가 다시 실행되지 않아요.
- `v` 명령은 무시돼요.
- `p`와 `x`만 받아요.
- **보드를 재부팅하기 전까지 풀리지 않아요.** 이름에 래치(latch, 걸쇠)가 붙은 이유예요.

## 에필로그: 명령 하나의 여정 요약

```
PC: "v 0.3 -0.1\n"
  │
  ▼ readCommands()     글자 모으기, 수상하면 정지
  ▼ command()          검사 → requested = {12, -4}, 시각 기록
  │                    (모터에는 아직 아무것도 안 씀)
  ▼ (최대 10ms 대기)
  ▼ readPosition()     위치 / 토크 / HW에러 / 워치독 점검
  ▼ writeSpeed()       Profile = {12, 4}, Goal = {팬 오른쪽 끝, 틸트 아래쪽 끝}
  │                    SyncWrite → SyncRead로 검증
  ▼ 모터               설정 속도로 목표를 향해 이동
  │
  ├─ PC가 계속 v를 보냄 → 계속 이동, 한계에 닿으면 스스로 감속 후 정지
  ├─ PC가 200ms 침묵     → stopMotion(), 제자리 유지
  ├─ 보드가 멈춤          → 모터 워치독(200ms)이 스스로 정지
  └─ 이상 감지            → latchFault(), 재부팅 전까지 정지
```

한 줄로 요약하면, **"PC는 원하는 속도를 계속 말해 주고, 보드는 10ms마다 상태를 확인하면서 그 속도를 안전한 범위 안의 위치 목표로 바꿔 전달하는 문지기"**예요.

특정 함수나 줄을 더 파고들고 싶으면 말씀해 주세요.

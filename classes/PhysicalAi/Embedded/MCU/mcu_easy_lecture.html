4강 · MCU와 주변장치 (Cortex-M · GPIO · 인터럽트 · 타이머 · PWM)

로봇의 “반사신경 컴퓨터” 이해하기

중학생도 따라올 수 있게, 원문의 핵심 개념·수식·그림·표를 빠짐없이 풀어쓴 학습용 해설입니다.

1. 한 줄 요약

MCU는 로봇의 센서를 읽고, 정확한 시간에 계산하고, 모터에 명령을 보내는 작은 실시간 컴퓨터이며, GPIO·인터럽트·타이머·PWM은 그 일을 하는 핵심 도구입니다.

2. 왜 배우나 — 실제 로봇에서는 어디에 쓰나?

PID 식을 아무리 잘 만들어도 식만으로 모터는 돌지 않습니다. 로봇이 실제로 움직이려면 센서를 읽고 → PID를 계산하고 → 모터 드라이버에 출력하는 일을 예를 들어 정확히 1 ms마다 반복해야 합니다. 이 “정확한 반복”을 MCU가 담당합니다.

flowchart LR A[엔코더/버튼 등 센서] -->|GPIO·Timer 입력| B[MCU] B --> C[1 ms마다 PID 계산] C -->|PWM 크기| D[모터 드라이버] C -->|GPIO DIR 방향| D D --> E[DC 모터] E --> A

원문 p.3, p.8, p.11의 흐름을 합쳐 재구성.

3. 선수 지식 체크

0과 1
디지털 신호는 보통 Low(0) / High(1)로 생각합니다.
전압 V
STM32 GPIO 논리 신호는 대표적으로 0 V와 3.3 V를 사용합니다.
주파수 Hz
1 Hz = 1초에 1번, 1 kHz = 1초에 1000번입니다.
주기 T
[보충] 주파수가 f이면 주기는 T=1/f입니다. 1 kHz라면 T=1 ms입니다.
주소
컴퓨터가 데이터가 있는 위치를 찾기 위한 번호입니다.
비트(bit)
0 또는 1 한 칸. 레지스터의 특정 비트를 바꿔 하드웨어를 설정합니다.

4. 핵심 개념

4-1. MCU(Microcontroller Unit) — 로봇의 반사신경용 작은 컴퓨터

비유: PC가 “큰 사무실”이라면 MCU는 “기계 바로 옆에서 버튼과 모터를 즉시 다루는 전담 기사”입니다. 사무실은 더 강력하지만, 전담 기사는 정해진 순간에 바로 반응하기 쉽습니다.

정의: 마이크로컨트롤러(Microcontroller Unit, MCU)는 CPU 코어, 코드 저장용 Flash, 작업용 SRAM, GPIO·타이머·통신 같은 주변장치(peripheral)를 한 칩에 넣은 작은 컴퓨터입니다. 강의에서는 STM32와 Arm Cortex-M 코어를 사용합니다.

원문 p.3 그림 설명: Cortex-M4 CPU 코어가 Flash와 SRAM을 사용하고, AHB/APB 버스를 통해 GPIO, Timer/PWM, ADC, UART, SPI/I2C, Encoder Interface 같은 주변장치에 연결됩니다. 주변장치에서 급한 사건이 생기면 NVIC가 CPU에 인터럽트를 전달합니다.

4-2. 메모리맵(Memory Map) — “모든 것은 주소다”

비유: 아파트에서 “101호=Flash, 202호=SRAM, 401호=GPIO”처럼 방마다 주소가 있다고 생각하면 됩니다. MCU는 주소를 보고 어디에 읽고 쓸지 결정합니다.

정의: Cortex-M의 메모리 맵드 입출력(Memory-Mapped I/O)은 코드, 변수뿐 아니라 하드웨어 제어 레지스터(register)도 같은 주소 공간에 놓는 방식입니다. 그래서 주변장치를 다룬다는 것은 결국 정해진 주소의 레지스터에 값을 읽거나 쓰는 것입니다.

대표 주소 영역원문에서 설명한 내용
0x0800 0000 부근Flash — 프로그램 코드, 전원이 꺼져도 유지
0x2000 0000 부근SRAM — 전역/지역 변수, 스택
0x4000 0000 부근주변장치 레지스터 — GPIO·Timer·ADC 설정/데이터
// bare-metal: GPIOA 출력 데이터 레지스터의 5번 비트를 1로
GPIOA->ODR |= (1 << 5);

// HAL: 위와 같은 목적을 더 읽기 쉬운 함수로 표현
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);

첫 코드는 레지스터를 직접 만지고, 두 번째는 하드웨어 추상화 계층(Hardware Abstraction Layer, HAL) 함수가 대신 만집니다. 겉모양은 달라도 마지막에는 레지스터가 바뀝니다.

4-3. 툴체인(Toolchain) — 내가 쓴 코드가 칩에 들어가기까지

비유: C 코드는 “설계도”, 컴파일러는 “번역가”, 링커는 “창고 배치 담당”, ST-LINK는 “칩에 실제로 새기는 기계”입니다.
flowchart LR S[Source .c/.cpp] --> C[Cross Compile
arm-none-eabi-gcc] C --> L[Link
Linker Script가 Flash/SRAM 배치] L --> F[.elf / .bin] F --> ST[ST-LINK] ST --> FLASH[MCU Flash에 기록] FLASH --> R[Reset 후 실행]

크로스 컴파일(cross compile)은 지금 코드를 작성하는 PC의 CPU가 아니라 다른 CPU인 Cortex-M용 기계어를 만드는 것입니다. STM32CubeIDE는 편집기, 컴파일러, 플래셔, 디버거와 CubeMX 핀 설정 GUI를 묶어 제공합니다.

4-4. GPIO(General-Purpose Input/Output) — 디지털 손발

비유: GPIO 출력은 손가락으로 스위치를 켜고 끄는 것, GPIO 입력은 손끝으로 버튼이 눌렸는지 느끼는 것과 비슷합니다.
출력(Output)
핀을 High(예: 3.3 V) 또는 Low(0 V)로 만듭니다.
예: LED, relay, motor driver DIR.
입력(Input)
핀의 전압 상태를 0/1로 읽습니다.
예: button, limit switch, encoder signal.

풀업/풀다운(pull-up/pull-down): 입력 핀이 아무것에도 확실히 연결되지 않으면 floating 상태가 되어 0과 1이 불안정하게 바뀔 수 있습니다. 내부 저항을 이용해 기본값을 High 또는 Low로 정해 줍니다.

실생활 예: 로봇청소기 범퍼 스위치 = GPIO 입력, 상태 LED = GPIO 출력.

4-5. 인터럽트(Interrupt) — 계속 물어보지 말고, 사건이 생기면 불러!

비유: 폴링은 1초마다 문을 열어 “택배 왔어요?”라고 묻는 방식이고, 인터럽트는 초인종이 울리면 바로 문을 여는 방식입니다.

폴링(polling)은 메인 루프에서 상태를 계속 확인합니다. 인터럽트(interrupt)는 하드웨어 이벤트가 생기면 CPU가 현재 일을 잠시 멈추고 인터럽트 서비스 루틴(Interrupt Service Routine, ISR)을 실행한 뒤 원래 코드로 돌아옵니다. Cortex-M에서는 NVIC(Nested Vectored Interrupt Controller)가 이를 관리합니다.

원문 p.6 그림 설명: 폴링에서는 “확인 → 다른 일 → 확인” 사이에 이벤트가 생기면 다음 확인까지 기다립니다. 인터럽트에서는 이벤트 순간 NVIC가 ISR을 호출하고, ISR이 끝나면 메인 루프로 복귀합니다.
sequenceDiagram participant Main as Main Loop participant HW as Hardware Event participant NVIC as NVIC participant ISR as ISR Main->>Main: 다른 일 수행 HW-->>NVIC: 이벤트 발생 NVIC-->>Main: 현재 흐름 잠시 중단 NVIC->>ISR: ISR 호출 ISR->>ISR: flag/value만 짧게 처리 ISR-->>Main: return Main->>Main: 원래 일 계속

ISR 규칙: 짧게 끝냅니다. 플래그를 세우거나 값을 저장하고 바로 return. 원문은 ISR 안에서 printf, delay, 무거운 계산을 피하라고 강조합니다. 오래 잡고 있으면 더 중요한 제어 인터럽트가 밀릴 수 있습니다.

[보충] ROS2 callback과 생각 방식은 비슷합니다. “이벤트가 오면 등록된 함수를 실행”합니다. 다만 ISR은 훨씬 더 엄격하게 짧고 예측 가능해야 합니다.

4-6. 타이머(Timer) — MCU의 정확한 심장박동

비유: 84 MHz 시계는 너무 빠른 초고속 메트로놈입니다. PSC는 박자를 느리게 나누고, ARR은 “몇 박을 세면 한 번 알람을 울릴지” 정합니다.

정의: 타이머는 클럭을 세는 하드웨어 카운터입니다. 시스템 클럭을 프리스케일러(Prescaler, PSC)로 나누고, 카운터가 자동 재적재 레지스터(Auto-Reload Register, ARR)에 도달하면 이벤트를 냅니다.

원본 수식
\( f_{이벤트} = \dfrac{f_{클럭}}{(PSC+1)(ARR+1)} \)

기호
f클럭 = 타이머 입력 클럭 (Hz)
PSC = 프리스케일러 레지스터 값 (정수, 단위 없음)
ARR = 자동 재적재 값 (정수, 단위 없음)
f이벤트 = 초당 타이머 이벤트 횟수 (Hz)

이 식이 하는 일: “원래 시계가 너무 빠른데, 두 단계로 나눠서 내가 원하는 속도의 알람을 만들자”입니다. PSC가 첫 번째 감속기, ARR이 두 번째 카운트입니다. +1이 붙는 이유는 레지스터가 0부터 세기 때문입니다.

숫자 예제: f클럭=84,000,000 Hz, PSC=83, ARR=999라면
\(f = 84,000,000 / ((83+1)(999+1)) = 84,000,000/(84\times1000)=1000\,Hz\).
즉 1초에 1000번 = 1 ms마다 이벤트가 생깁니다.

서보 예: PSC=83, ARR=19999라면 \(84,000,000/(84\times20000)=50\,Hz\). 주기는 \(T=1/50=0.02s=20ms\)입니다.

타이머의 세 가지 핵심 용도는 ① 주기 인터럽트 ② PWM 출력 ③ 엔코더 카운팅입니다. 강의에서는 1 kHz 주기 인터럽트로 이산 PID의 \(\Delta t=1ms\)를 만들고, PWM과 엔코더에도 타이머를 사용합니다.

왜 sleep(0.001)보다 타이머인가? 소프트웨어 지연은 다른 코드나 OS 상황 때문에 흔들리는 지터(jitter)가 생길 수 있습니다. 하드웨어 타이머는 클럭을 직접 세므로 훨씬 일정한 기준을 만들 수 있습니다.

4-7. PWM(Pulse Width Modulation) — 0/1만으로 중간 세기 만들기

비유: 수도꼭지를 반만 여는 대신, 아주 빠르게 “완전히 열기/완전히 닫기”를 반복하되 열려 있는 시간을 절반으로 만들면 평균적으로 절반 정도 공급되는 것과 비슷합니다.

정의: 펄스 폭 변조(Pulse Width Modulation, PWM)는 디지털 출력을 매우 빠르게 On/Off하고, 한 주기에서 High인 시간 비율인 듀티 사이클(duty cycle)을 조절하는 방법입니다.

원문 p.9 그림 설명: 25%, 50%, 75% duty 파형이 위에서 아래로 그려져 있습니다. duty가 커질수록 High 구간이 길어지고 점선으로 표시한 평균 전압도 올라갑니다.
원본 수식
\( V_{평균} = V_{전원} \times duty \qquad (0 \le duty \le 1) \)

기호
V전원 = 모터 전원 전압 (V)
duty = 듀티 사이클 (0~1, 단위 없음)
V평균 = 강의에서 모터가 느끼는 평균 전압으로 설명한 값 (V)

이 식이 하는 일: “전체 전압 × 켜져 있는 시간 비율”로 평균 효과를 계산합니다. 모터는 기계적 관성 때문에 충분히 빠른 On/Off를 하나하나 따라가지 못하고 평균적인 효과를 받는다고 설명합니다.

숫자 예제: 12 V 전원에서 duty=0.30이면 \(V_{평균}=12\times0.30=3.6V\). 50%라면 약 6 V에 해당하는 평균 효과입니다.

주의: 이 식은 강의의 직관적 모델입니다. 실제 DC 모터 전류·토크·속도는 역기전력, 권선 저항/인덕턴스, 드라이버 손실, 부하 등에 영향을 받으므로 “duty 50% = 실제 속도 정확히 50%”라는 뜻은 아닙니다.

DC 모터 PWM vs RC 서보 PWM

대상주파수/주기명령의 핵심강의의 예
DC motor보통 수 kHz~20 kHz 등duty가 세기 명령PID 출력 크기 → duty

즉 “PWM이면 전부 duty가 명령”은 아닙니다. RC 서보에서는 주기를 20 ms로 두고 High 펄스의 절대 시간 폭을 사용합니다.

4-8. PID 출력 → PWM + DIR → 모터

원문 p.11의 연결은 매우 중요합니다. PID 출력 \(u\)가 예를 들어 -1~+1이라면, 부호(sign)는 회전 방향을 정하는 GPIO DIR 핀으로, 크기(|u|)는 PWM duty로 보냅니다.

flowchart LR U[PID output u
-1 ~ +1] --> S{sign of u} S -->|+| F[DIR = Forward] S -->|-| R[DIR = Reverse] U --> A[abs(u)] A --> D[PWM duty 0~100%] F --> M[Motor Driver / H-Bridge] R --> M D --> M M --> MOTOR[DC Motor]

4-9. 모터 드라이버와 H-브리지

비유: MCU는 “지시하는 뇌”라서 작은 신호만 낼 수 있고, 모터 드라이버는 “힘센 근육”처럼 큰 전류를 모터에 공급합니다.

MCU GPIO는 모터에 필요한 수 A를 직접 공급할 수 없습니다. 그래서 L298N, DRV8871 같은 모터 드라이버 또는 브러시리스 모터용 ESC를 사이에 둡니다. H-브리지는 스위치 4개를 이용해 모터에 흐르는 전류 방향을 뒤집어 회전 방향을 바꾸는 회로입니다.

강의는 모터 전원과 MCU 전원을 분리하고 GND를 공통으로 묶는 구성을 강조합니다. 모터의 전기적 노이즈가 MCU 리셋을 일으킬 수 있기 때문입니다.

헷갈리는 생각실제로는
“MCU는 PC보다 느리니까 제어에도 불리하다.”클럭 속도보다 예측 가능한 시간 반응이 Hard real-time에서 중요합니다.
“HAL 함수는 하드웨어와 별개다.”HAL도 결국 주변장치 레지스터를 읽고 쓰는 일을 대신합니다.
“입력 핀은 아무것도 안 누르면 자동으로 0이다.”pull-up/down이 없으면 floating되어 값이 흔들릴 수 있습니다.
“인터럽트는 빠르니까 ISR 안에서 다 계산하면 된다.”ISR은 짧게. 오래 걸리면 다른 중요한 인터럽트가 지연됩니다.
“PSC=83이면 83으로 나눈다.”0부터 세므로 실제 분주 계수는 PSC+1=84입니다.
“ARR=999면 999번 센다.”0~999까지 세므로 총 1000 counts입니다.
“PWM 50%면 핀에서 1.65 V가 계속 나온다.”핀 자체는 0/High를 빠르게 반복합니다. 부하가 평균 효과를 느끼는 것입니다.
“모든 PWM 장치는 duty로 명령한다.”DC 모터는 duty가 핵심이지만 RC servo는 보통 pulse width가 위치 명령입니다.
“MCU가 모터에 직접 전력을 준다.”MCU는 논리 신호를 주고, 큰 전류는 motor driver/H-bridge가 담당합니다.

8. 셀프 체크 — 5문제

Q1. MCU가 로봇의 Hard real-time 제어에 잘 맞는 핵심 이유는?

정답: 단순히 클럭이 빠르기 때문이 아니라, 타이머와 인터럽트를 이용해 예측 가능한 시점에 반복적으로 반응하기 좋기 때문입니다.

Q2. GPIO 입력에 pull-up/down이 없으면 왜 문제가 생길까?

정답: 입력이 floating 상태가 되어 전압이 확정되지 않고 0/1이 불안정하게 읽힐 수 있습니다.

Q3. 84 MHz, PSC=83, ARR=999이면 타이머 이벤트 주파수와 주기는?

정답: \(84,000,000/(84\times1000)=1000Hz\). 따라서 주기는 \(1/1000s=1ms\)입니다.

Q4. 12 V 전원, PWM duty=30%라면 강의의 평균 전압 모델에서는 얼마인가?

정답: \(12\times0.30=3.6V\).

Q5. PID 출력 u=-0.7을 DC 모터에 보낸다면 개념적으로 GPIO와 PWM은 어떻게 나눠 맡을까?

정답: 음수라는 부호는 DIR GPIO로 역방향을 선택하고, 크기 \(|-0.7|=0.7\)는 PWM duty 약 70%에 대응시킵니다. 실제 드라이버 API/배선 방식에 따라 논리 레벨은 달라질 수 있습니다.

마지막 연결 문장

“MCU에서 주변장치를 다룬다” = 레지스터를 읽고/쓴다 → GPIO로 디지털 신호를 다룬다 → Timer로 정확한 시간을 만든다 → Interrupt로 제때 함수를 실행한다 → PWM으로 모터에 세기 명령을 보낸다.

GIT / QUICK GUIDE 04 STEPS

깃 레포지토리 복사법

외부 레포지토리를 내 레포지토리로 옮기는 4단계.

외부 레포지토리→내 컴퓨터→내 레포지토리
  1. 01

    내 레포지토리 만들기

    GitHub에서 내 계정으로 빈 레포지토리를 만듭니다.
    README, .gitignore, 라이선스 파일은 초기 생성 옵션에서 추가하지 마세요.

    내 레포지토리 주소 예시https://github.com/YOUR-USERNAME/my-repo.git

    아래 예시의 소유자·레포지토리 이름은 실제 주소에 맞게 바꿔주세요.

  2. 02

    외부 레포지토리 clone

    터미널에서 원본을 내려받고, 복제된 폴더로 이동합니다.

    TERMINAL · 원본 주소
    git clone https://github.com/ORIGINAL-OWNER/source-repo.git
cd source-repo

    폴더 이름도 실제 레포지토리 이름으로 바꿉니다. 이후 명령은 이 폴더 안에서 실행하세요.

  3. 03

    내 레포지토리를 remote로 연결

    1단계에서 만든 내 레포지토리를 public이라는 이름으로 추가합니다.

    TERMINAL · 내 레포지토리 주소
    git remote add public https://github.com/YOUR-USERNAME/my-repo.git
    origin 외부 원본public 내 레포지토리

    public은 remote의 별칭입니다. 저장소의 공개·비공개 설정과는 관계없어요.

  4. 04

    내 레포지토리에 push

    로컬 main 브랜치를 내 레포지토리의 main으로 올립니다.

    TERMINAL · main 브랜치 기준
    git push public main
    실행 전, 브랜치 이름을 확인하세요.위 명령은 로컬에 main이 있을 때 사용합니다. 현재 브랜치는 git branch --show-current로 확인하세요. 복사할 현재 브랜치가 develop이면 git push public develop을 사용합니다.

    push가 끝나면 GitHub에서 내 레포지토리의 파일과 커밋을 확인합니다. 인증이 필요하며, 내 레포지토리에 쓰기 권한이 있어야 합니다.

어디까지 복사되나요?

선택한 브랜치의 파일과 그 브랜치에서 이어지는 커밋 기록이 전송됩니다. 모든 브랜치·태그, Issues, PR, 저장소 설정을 한 번에 옮기는 방법은 아닙니다. Git LFS·서브모듈은 별도 확인이 필요합니다.

올리기 전에 확인

원본의 복사·재배포 권한과 라이선스를 확인하세요. 공개 저장소로 올릴 때는 파일과 과거 커밋에 비밀번호·API 키 등 민감한 정보가 없는지도 확인합니다.
